## 2025-06-25 - [CRITICAL] Prevent Application-Layer DoS via Unhandled ASGI Middleware Exceptions
**Vulnerability:** The `RequestSizeLimitMiddleware` intercepted chunked requests and attempted to reject large payloads by raising `fastapi.HTTPException` directly from within the overridden `request._receive` async generator. However, ASGI servers running Starlette expect exceptions inside the underlying body streaming generator to either gracefully disconnect or be of specific types. Raising an `HTTPException` inside `_receive` causes the internal TaskGroup reading the stream to crash ungracefully, resulting in an unhandled 500 error that bubbles past all FastAPI exception handlers.
**Learning:** You cannot throw application-level HTTP Exceptions from within an ASGI request body stream interceptor (`request._receive` or `request.stream()`) because the exception bypasses standard HTTP handlers and directly hits the server's internal task group. Also, moving local imports (like `from fastapi.responses import JSONResponse`) out of `except` blocks in middleware helps prevent `UnboundLocalError`.
**Prevention:** When building custom middleware to reject large streams mid-flight, raise `starlette.requests.ClientDisconnect` inside the `receive` function to safely abort the ASGI data stream. Then, catch the `ClientDisconnect` exception (and check for `ExceptionGroup` wrapping in AnyIO 4+) in the outer `dispatch` block (around `await call_next(request)`) and manually return a `413 JSONResponse`. Ensure imports used in exception handlers are placed at the top of the file to prevent `UnboundLocalError`.
